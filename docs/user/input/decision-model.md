除了随包的小模型, 青简还能把整句候选交给 "决策模型" 再排一次. 这类模型不写文章, 只回答一个问题:
这几条候选里, 哪一条接在前文之后最顺. 它一次就算完, 不用一个字一个字地生成.

## 两种接法

- **本地服务**: 自己在电脑上跑一个模型服务 (模型权重, 跑在哪张显卡上都由你决定, 服务地址缺省是
  `http://127.0.0.1:8080/api/predict`). 全程离线, 内容不出这台电脑.
- **云端**: 填一个云端服务地址与密钥, 由对方算. 光标前的几十个字会随请求发出去, 其余内容不发.

## 怎么开

在 "偏好设置 > 云服务" 里勾上 "决策模型重排", 选后端, 填接口地址 (留空用缺省值); 选云端时再填密钥,
密钥写进配置目录的 `.env`, 不会显示回填的值. 也可以直接改配置文件:

```toml
[decision]
enabled = true
backend = "laya"
endpoint = ""
```

开着决策模型时, 上面的 "本地整句模型" 不再生效: 两者占同一个位置, 谁也没有必要同时跑.
决策模型起不来 (地址不对, 密钥没填, 服务没启动) 时自动退回本地整句模型, 两个都用不了就按词库统计出句.
云端一次判断要一两秒, 选出来的顺序会比本地模型晚一点才换上去; 等多久跟着配置里的 `[decision] timeout_ms` 走, 超时这一轮就不换.
被模型重排过的候选后面会带一个小标, 形如 `AI 87%`: 那是模型给这条候选的把握 (概率), 只在接决策模型时出现.

## 什么时候不生效

与本地整句模型一样: 翻过页或动过高亮之后不再改正在看的这页; 密码框里不组句; 应用声明为私密的输入框里
青简不会把内容交给云端后端 (本地服务不受影响).

## 关掉

取消勾选, 或配置文件里写 `enabled = false`. 关掉之后回到本地整句模型.

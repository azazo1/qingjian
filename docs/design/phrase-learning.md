# 记词组

## 是什么

在应用里选中一段文字, 按一个可配的快捷键, 输入法读出选区并给出它的拼音, 回车把 "拼音 -> 文本" 记成一条用户词.
下次敲这段拼音, 这个词就是候选; 因为同时按该输入串记了一次选择, 它排在同一输入串下最前.
效果等于用户敲过这段拼音、再从候选里选中这段文本上屏.

## 为什么记成用户词

候选里的词要么来自词库, 要么是用户选过 / 云端给过的用户词 (`Learner::learn_word`).
词库覆盖不到的名字、术语、编号以前只能靠先打一遍再选一次. 记词组把这条路径省掉: 文本已经在应用里了, 不必重打, 只要给出拼音.

不放进自定义短语 (`CustomPhrase`): 那里的键是字母输入码 (`rq` / `ee`), 与拼音音节无关, 位置也是固定的;
用户词按音节查, 与普通输入走同一条路.

## 交互

- 触发: `[shortcut] learn_phrase`, 修饰键 + 一个字母, 缺省 `none` (要用得自己配).
  与翻译选中文字同一层判定: 不在组句中才认这个键.
- 读选区: macOS 走 IMK 的 `selectedText` (上限 500 字, 与翻译一致), Windows 复用翻译的 `RequestSelection` / `Selection` 协议.
  请求带上用途, 回包按用途分流到翻译或记词组.
- 评审态: 拼音行显示正在编辑的拼音 (预填反查结果, 音节之间用 `'`), 旁边给一句 "回车记词组 · Esc 取消".
  字母与 `'` 追加, 退格删末位, 回车提交, Esc 放弃, 其余键吞掉不动.
- 应用里的内容全程不动: macOS 不放 marked text, Windows 回给 DLL 的帧不带 preedit (只带 `reviewing` 标志, Server 自绘的候选窗照常显示拼音与提示).
  拼音只活在壳里那份字符串里, 这是评审态与普通组句最大的区别.

## 拼音从哪来

`qingjian-core::transcribe::Transcriber` 按词库反查读音: 先按语言模型把句子切成词、整词查, 词库没有的词退到逐字查,
多音字取词库里的词 (或该字词频最高的读音) 的读法. 它与 `apps/cli` 整句评测把中文原文转拼音用的是同一张表, 所以从 CLI 搬进了 Core.

`Engine::pinyin_of` 惰性建表并缓存 (建表要遍历全部词库, 几十毫秒级, 只付一次), `set_extra_dictionaries` 时作废.
有字查不到读音就返回 `None`, 壳预填空串让用户手敲; 非汉字字符不参与反查 (与评测转拼音的口径一致).

## 记账

`Engine::remember_phrase(pinyin, text)` 与 "敲了这段拼音并选中这个文本上屏" 是同一笔账:

- `Learner::learn_word(text, syllables)`: 文本进用户词表 (`user-words.tsv`), 同一个文本原来的拼音被换掉;
- `Learner::record_choice(字母串, text)`: 在该输入串下记一次选择, 于是词级排序里它排最前;
- `Learner::record(candidate)`: 计一次用户选择.

拼音串按 `parser::segment` 切分 (分隔符可以是 `'` 或空白), 每个音节都要求完整; 切不动或带残音节返回错误, 壳留在评审态让用户接着改.
私密输入中与用户关掉学习时返回错误、什么都不记.

## 边界

- 无选区、应用不给读选区: 提示一句, 不进评审态.
- 文本与音节数不一致 (含英文、标点、数字): 不拦. 词库按音节序列匹配, 文本长度无关.
- 同一个文本重复记: 换掉旧拼音并提示 "已更新".
- 私密输入与 `[general] learning = false`: 都不记, 壳给出对应提示.
